# Jira

Needs `sources.jira.site`, `cloudId` and `projects`. The scheduler's preflight reads Jira with `JIRA_EMAIL` and `JIRA_API_TOKEN`; the rest of a pass uses the Atlassian MCP server (`node "${CLAUDE_PLUGIN_ROOT}/scripts/mcp.mjs" enable atlassian`, then `/mcp` to log in once). If that login does not survive unattended runs (the Atlassian server's OAuth does not, and its API-token mode offers no Jira tools), use the token server this plugin ships: `node "${CLAUDE_PLUGIN_ROOT}/scripts/jira-mcp-config.mjs"` adds a `jira` entry to `.mcp.json` that holds no secret (only the host), and `scripts/jira-mcp.mjs` reads `JIRA_EMAIL` and `JIRA_API_TOKEN` from the environment of the pass (`~/.dev-factory/.env.local`). It offers the tool names this file uses (`getJiraIssue`, `searchJiraIssuesUsingJql`, `getTransitionsForJiraIssue`, `transitionJiraIssue`, `addCommentToJiraIssue`, `editJiraIssue`, `createJiraIssue`, `addRemoteLinkToJiraIssue`, `lookupJiraAccountId`, `uploadAttachmentToJiraIssue`); `[~accountid:ID]` in a comment body becomes a real mention.

Status names are `sources.jira.states`; the defaults are Ready for Dev / To Do (ready), In Progress, Peer review (inReview), Ready for QA (reviewed), Done. Add the statuses your workflow uses after review to `states.done` (for example UAT, Ready for Release); they count as done for blockers and validation. `requireSprint: true` limits the queue to issues in an open sprint.

Workflows differ per issue type and project, so never assume a transition exists or is called what you expect: to move an issue, fetch its transitions and pick the one whose target status (`to.name`) is the status you want, whatever the transition is named. If none is offered, do not improvise: leave the status, comment `[dev-factory] transition to <status> not available for this issue type`, and carry on.

Searches (always quote project keys: `MAX` and others are reserved words):

-   ready: `project in ("A","B") AND assignee = currentUser() AND labels = "<tasks.label>" AND labels != "<tasks.blockedLabel>" AND status in (<ready names>) ORDER BY Rank ASC` (add `AND sprint in openSprints()` when `requireSprint`)
-   stale: same filter with `status = "<inProgress>" AND updated <= -<caps.stallMinutes>m`
-   breaker: `labels = "<tasks.blockedLabel>" AND labels != "<tasks.questionLabel>" AND status not in (<done names>) AND updated >= -<caps.breakerWindowHours>h` (a finished issue and a question waiting for a person are not failures)
-   leftover parks: `labels in ("<tasks.blockedLabel>", "<tasks.questionLabel>") AND status in (<done names>)`, cleared in the housekeeping step with `editJiraIssue` and `update.labels` set to `[{"remove": "<tasks.blockedLabel>"}, {"remove": "<tasks.questionLabel>"}]` (`tasks.mjs unblock` refuses a Jira source: its writes go through the MCP server; `editJiraIssue` takes `update.labels` only, not Atlassian's `fields`). The same call clears both labels when a person answered a question
-   validation: `... AND labels not in ("factory-validated","factory-regression") AND status in (<done names>) AND updated <= -<validation.minHoursAfterMerge>h AND updated >= -30d`

Blockers are `is blocked by` links: a blocker counts as done when its status is in `states.done` or its status category is Done. Read them with the issue. `kind` comes from the issue type: a type in `tasks.bugTypes` is `bug`; Story, Epic and Feature are `story`; Improvement is `improvement`; everything else is `task`.

LINK: add the branch and the PR as remote links on the issue (the Atlassian MCP's remote-link tool; `gh repo view --json url` gives the repository URL), put the QA verdict in the comment, and attach the evidence. With the token server: `node "${CLAUDE_PLUGIN_ROOT}/scripts/evidence.mjs" plan --worktree <worktree> --run <N>` lists what may be attached (files of the finished run, each hashed in its manifest, none over `evidence.maxAttachmentMb`; what is left out is named) and writes `summary.md` (the verdict, each case, the diff and key hunks, short excerpts, all redacted); then call `uploadAttachmentToJiraIssue` once per name with `{issueIdOrKey, worktree, run, fileName}`; a file already attached with the same name and size is skipped. Without an attachment tool, the comment names the PR, where the screenshots are.

Comments for people are short and tagged (see `scripts/comment-lib.mjs`): the assignee and reporter first, one paragraph, and a `[dev-factory] <kind>` marker line last. A person's answer to a question is a comment without a marker line after it; the scheduler's preflight reads comments through the REST API (`tasks.mjs comments <KEY>` equivalent) to see it and any `dev-factory fix` request on the ticket. `tasks.mjs list` for jira exits 21 without `JIRA_EMAIL` and `JIRA_API_TOKEN`: Jira answers an unauthenticated search with an empty list, which must never read as an empty queue.

Create issues with the project's own issue-creation skill if one exists, else with the MCP create tool: label `tasks.label`, assignee the factory user, a link for each blocker, blockers first.
