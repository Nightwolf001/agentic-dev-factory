# Improvement plan

Proposals for changing the factory itself, written by `/dev-factory:improve` from the run records, merged learnings and blocked or regressed tickets. It is a list for a person to decide on: improvement issues carry the label `dev-factory-improvement`, never `dev-factory`, so the factory does not build changes to itself unattended. A person reviews each draft PR and merges it.

## Proposals from a design review

These come from reading the factory's own flow against published practice for unattended coding agents, not from run records, so the scan does not own or rewrite them. Each is a proposal for a person to decide on, ranked by value over effort. Items 1 to 3 were re-read against the code at 0.19.0; the rest were found by a review and need a read of the named files before work starts. Every item that changes `bin/qa.mjs`, `scripts/stop-gate-lib.mjs`, `scripts/run-record.mjs` or `scripts/config.mjs` needs a test in `test/`.

The principles behind the ranking: completion is proven by the harness, not claimed by the agent; every budget has code behind it; the builder cannot weaken what judges it; a reviewer starts with fresh context; and state survives a lost context.

1. **Make `build.done` mean something.** `scripts/stop-gate-lib.mjs` accepts the file by existence alone, so nothing checks a clean tree, a passing QA record at HEAD, or that the file names HEAD. A premature hand-off costs review rounds and is caught only at ship. Change `decide()` to require all three. Test: a new `test/stop-gate.test.mjs`. Risk: low.
2. **Fail closed when the stop gate gives up.** After `DF_STOP_GATE_MAX` nudges `scripts/stop-gate.mjs` exits 0 with nothing recorded, and the pass waits for the stall rule. Write `blocked.json` with the unmet step as the reason, and never overwrite a valid marker. Test: `test/stop-gate.test.mjs`. Risk: low.
3. **Enforce the budgets that are only prose.** `caps.maxQaFixAttempts` is set in `config.json` and documented but no script reads it, and `skills/qa/SKILL.md` hard-codes five. Make `qa.mjs start` refuse once failed runs reach the cap and tell the builder to block for a person. Test: `test/qa.test.mjs`. Risk: low.
4. **Run tests through the factory.** Test counts are recorded as reported, so "red first" and "green at HEAD" cannot be proven. Add a `qa.mjs test run` that records exit code, parsed counts and HEAD, and require a green run at HEAD for `build.done`. It has to work with containerised commands and the shell guard. Tests: `qa`, `coverage` and `guard` suites. Risk: medium.
5. **Scan the diff for weakened tests.** Nothing detects deleted tests, added skip or only markers, snapshot churn or lowered assertions, and test paths count as no-behaviour changes. Add a facts scan of the branch diff that is passed into the reviewer prompt, advisory first and configurable by glob. Test: `test/qa.test.mjs`. Risk: medium.
6. **Keep a criteria ledger.** "A case per acceptance criterion" is prose, the non-strict ticket lint accepts any 12-character line as a criterion, and the reviewer is not told to read the QA cases. Extract the bullets at claim, have the builder map each to a test and a case, and refuse unmapped ones at `qa.mjs start` and in the stop gate. Tests: `ticket` and `qa` suites. Risk: medium.
7. **Cap waits by wall-clock time and record per-ticket cost.** A builder that keeps committing never trips the stall rule and is stopped only by the whole-pass spend cap, which starves later tickets. `run-record.mjs ticket` is called without cost or duration, so both are null and the scan cannot see them. Add a wait helper with stall and maximum minutes, a `caps.maxPhaseMinutes` setting, and a duration taken from `run.json`. Tests: a new wait test, plus config and settings-catalogue tests. Risk: low.
8. **Record the human outcome.** The run record says shipped and never learns whether the PR merged, was closed, needed fix passes or failed CI, so the scan sees only internal retries. Write an outcome record at the reviewed, done and closed transitions and use it as a clustering dimension. Test: run-record coverage. Risk: low.
9. **Publish research as a shareable page.** The researcher writes `docs/plans/<KEY>/research.md` for the builder, but a person has to open the repository to read it. Render the same findings as one self-contained page a person can open and forward, with each claim marked as read from a source or seen only in a search result, so a reader can tell what is verified. Test: whatever script renders it, per the list in `AGENTS.md`. Risk: low.

Later and unranked: derive the next phase from artifacts instead of tick prose, a `progress.md` hand-off for mid-phase context loss, and a reviewer on a different model family.
